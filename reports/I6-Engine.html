I6 Engine

A parametric inline-six engine authored, organised, animated and verified in nTop through the prototype Notebook API, with no clicks in the GUI.

6 SEP 2026nTop 6.0.0-rc, build 42594STATUS: BUILT AND VERIFIED

01Why this exists

The Notebook API lets a script add blocks, wire them and read values back in a live nTop notebook. This project tests whether that is enough to build a moving mechanical assembly at manufacturing detail, keep it organised, and prove the result numerically. The engine is the test article: one crank angle has to move six pistons, six rods, two camshafts, 24 valves and 24 springs, and every derived value has to match a closed-form model.

Summary

The engine is built, moves from one parameter, and matches its closed-form kinematics to 5e-6 mm at six crank angles (measured).

The notebook holds 1106 variables in 13 sections. A Python builder wrote it as one recipe and imported it in 26 minutes; the same build through single API calls was measured at over an hour and stopped. Part extents match the parameter table to 1.2e-5 mm. Two limits stand: a crank-angle change in the full notebook re-evaluates for over an hour, and nTop's bounding boxes of rotated bodies are padded, so three checks are one-sided bounds rather than equalities.

02One input moves everything

Change Crank Angle and the notebook re-evaluates the whole engine. Six pistons and rods follow the slider-crank equations. Two camshafts turn at half speed. Every valve lifts by the exact flat-follower lift of the tangent cam lobe above it, so the lobe nose stays in contact with its bucket at every angle. Each spring's pitch is the installed length minus the lift, so the spring compresses with its valve.

z_pin = r cos(th) + sqrt(L^2 - r^2 sin^2(th)) beta = -asin(r sin(th) / L) psi = th / 2 lift = max(0, d cos(psi - psi_c) + r_nose - R_base)

Firing order 1-5-3-6-2-4. Crank throws at 0, 240, 120, 120, 240 and 0 degrees. Intake centreline at 470 crank degrees, exhaust at 250.

04How it was built

A Python builder describes the engine as calls against the Notebook API. Building block by block was measured at 0.5 s or more per call once the notebook held a few hundred variables, over an hour for the engine. So the builder runs against a recording backend instead, writes one recipe, and import_recipe imports it in a single call: 1498 blocks, 1106 variables, 26 minutes (measured). The API cannot move blocks between sections, hide bodies or set colours, so a second tool rewrites the saved file: it orders the tree by section, writes the section ranges, hides every construction body, colours the 43 assembly bodies and frames the camera.

Measured on this build

Opening the notebook takes 85 s. One crank-angle change then re-evaluates for over an hour with 43 bodies visible and a 19 GB working set. The API call that sets the angle returns after 47 s; the first value read back blocks until the graph is done. Where the time goes has not been measured.

05Verification

Every kinematic value the notebook computes was read back through the API and compared with the same equations evaluated in plain Python. Why three checks are one-sided

nTop's bounding box of a rotated body is the box of the rotated box, and a polar array's box is padded. The measured box therefore contains the exact model and grows with the angle, but does not equal it. These rows prove containment, not position. Position is proven by the exact scalars above.

Found during verification

The first sweep reported the rod angle with the wrong sign at every angle where it is non-zero. The geometry was correct; the check variable was built by holding a negated reference, and the recipe's negative property is honoured as a block input but ignored as the contents of a variable. The builder now negates with a block. The lesson generalises: verify derived values at an angle where they are non-zero, not only at the rest position.

06Limits and next steps

If you want toThen
Change a dimensionEdit it in INPUTS, or in engine_spec.py and rebuild. Units in the GUI are inches and degrees; the recipe stores SI.
Animate in the live notebookExpect over an hour per angle with all bodies visible. Hide the block and head first, or use the 212-variable check notebook.
Export a partAdd the export after the build with engine.exports. Mesh tolerance below 1.0 mm dropped the valve core once and made the block export run for an hour; 1.0 to 1.5 mm exports whole.
Add the timing chain or manifoldsNot modelled. Gear and sprocket teeth are boxes on a polar array with no tip trim.
Blend edgesNot possible from the API; the blend enum on booleans cannot be set.
