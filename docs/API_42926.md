## Units and values

```python
notebook.set_block_input(sphere_id, 'Radius', 25.4, 'mm')
value = notebook.get_block_input(sphere_id, 'Radius')
unit = notebook.get_block_input_units(sphere_id, 'Radius')
```

The recorded probe returned `1.0` and `in`. Explicit setter units do not change the notebook's display units.
Record the requested value/unit and the returned value/unit separately. Recipes still store dimensioned SI values, including radians.
`set_block_input_units` preserves an already dimensioned quantity while rewriting its expression.
For a bare number, it attaches the specified unit. Getters do not recover the unit text originally entered.

The package reports that the first unit assigned to a dimensionless input fixes its dimension.
It also reports that point/vector setters accept explicit units, while `set_block_input_units` is limited to real/real_field inputs.
Do not assume those two methods support the same types. Read the live docstrings before a new probe.

Enums, lists, file paths, and direct `real_field` values still need a recipe or a suitable typed connection.
A real output can drive a real_field input. Recipe support is different from live setter support.
Do not silently coerce floats to integer inputs or integers to bool inputs.
Point/vector values have three components in the supplied skill. The recorded getter's two-item wording is a documentation error.
The supplied skill's later three-readable-types sentence is stale; its main type section and package README specify six.
Explicit live angle units replace the old manual conversion workaround. Recipe angles still use radians.

## Wrapper and connection rules

1. Set literals and connect the raw block's inputs before wrapping a computed block with `add_variable(name, raw_id)`.
2. Use the returned variable ID for every downstream consumer when an output has multiple consumers.
3. Rename an existing `core.var<T>` with `rename_variable`; wrapping it again can leave a second variable.
4. Get/set methods can look through variable wrappers for a named input. `list_block_inputs` reports the wrapper's own interface.
5. Do not assume `connect_block_property` traverses the target wrapper the same way. The propeller remesh case failed at this boundary.
6. A wrapper's `Input` can already contain its computed block. A connection does not reliably replace that occupied input.

The package reports successful clearing of raw inputs, nested blocks, and variable references on build 42926.
The propeller case still failed when clearing a wrapped computed input. These are different targets.
The clear docstring says an unchanged default can remain after a successful call. Inspect the input before reconnecting.
Inspect the exported graph after repair. If needed, finish a new raw block and then wrap it; retain the failed trial evidence.

A property reference is not a literal. `get_block_input` can raise on a connected point while the graph is connected correctly.
Use an evaluated downstream measurement or exported mesh. An exception alone does not prove a correct connection or value.
The recorded docstrings describe broader nested-ID access than the supplied skill's blanket warning.
Do not treat disappearance from `list_blocks` as deletion or assume every method resolves nested IDs identically.
Getters can read a wrapped computation, but a property connection is not the same kind of value.

## Lists and repeated geometry

The package demonstrates native list processing for repeated points, cylinders, and cuts.
Wrap reused list outputs before fan-out. A constant block count does not by itself prove the number or position of generated features.
Verify item counts and downstream geometry too.

Seed a `core.list<T>` before appending when a fresh input has no list. Some Bodies/Curves inputs already have empty lists.
`append_to_list` takes an input name as its third argument and appends the source output, not a named property.
The package reports a list-processing conflict for `add<real,real>` when a reducing `add<list<real>>` overload is available.
Check the exact overload and use an independently verified expression when that conflict occurs.
The supplied skill uses `round`, `floor`, and `ceiling` integer properties to drive counts from real-valued expressions.
Literal list growth uses a seeded core.list connected to a list-typed consumer, then appends to that consumer.

## Build state and completion

`e_DIRTY`, `e_QUEUED`, and `e_BUILDING` are incomplete evaluation states, not proof of failure or success.
`e_FAILED` carries failure text. `e_OK` is useful evidence after evaluation, but does not establish shape, dimensions, or solver quality.
Pause states are separate: `e_UNPAUSED`, `e_PAUSED`, and `e_RUN_ONCE`.
`e_UNBUILDABLE` and `e_WEAK` also exist. Their meanings are not established here; investigate them before acceptance.

Keep command completion separate from block evaluation and viewport rendering.
An exported recipe proves graph structure. A finished mesh export supports geometric checks.
A native screenshot verifies what the application rendered after GPU display catches up.
Opening a saved notebook can repeat expensive mesh evaluation; do not assume it is instantaneous.

## Transport and reproducible probing

Use [background dispatch](BACKGROUND_CONSOLE.md) with an explicitly owned process.
The existing window-message bridge remains supported. The optional [TCP helper](../scripts/ntop_tcp.py) requires a process identity record and a fresh run directory.
It verifies the loopback listener's PID, executable, and creation time before dispatch. It never retries a submitted command.
The package's original helper returns partial output on timeout; that is not reliable completion evidence.
This helper retains command, runner, transcript, and completion files instead.

The TCP service is an unauthenticated prototype interface. Keep it on loopback and do not forward its port.
A listening port does not prove which notebook is open. Select a task-owned scratch session before creating its identity record.

Run [the optional probe](../examples/probe_42926.py) only in an empty, task-owned notebook.
It does not clear or replace an existing notebook. This repo update did not run it against the user's current nTop sessions.
Capture `agent.api(notebook)` after future build changes. The harness reports feature presence without inferring a build number.

There is still no established live method to mark notebook inputs/outputs, set a camera, or delete a section.
The new import docstring says recipe inputs are added during import. Full Automate input/output authoring on build 42926 has not been independently verified here. The [generic assembly pilot](../.agents/skills/ntop-assembly-modeling/references/generic-pilot.md) retains separate build 42594 CLI evidence for that contract.
Do not carry forward the old blanket claim that no recipe workaround can exist.

## Wrapped mesh fields

The [later modeling review](RECENT_MODELING_LEARNINGS.md) records a successful incremental authoring route: independent groups contain complete local dependencies, then live connections bind their controls to shared variables. Inspect errors and save verified checkpoints. Existing exports can reevaluate during a small recipe import, so import size alone does not predict runtime.

Recorded build 42926 behavior: `list_block_inputs` and `connect_block_property` address the named block itself. They do not look through a variable wrapper. The scalar getter and setter can look through a wrapper, but a `real_field` parameter does not accept a dimensional numeric setter as a scalar `real` does.

For a mesh tolerance edit, connect a dimensional real variable to the actual mesh block's measured `Tolerance ` input before wrapping it. Preserve the trailing space in that name. The attempted clear of the old mesh wrapper's Input was refused. The successful recovery retained the new mesh block, removed the old export and mesh variables in dependency order, wrapped the new mesh with `add_variable`, and rebuilt Sharpen and Export. Keep failure receipts and verify the exported graph. A complete recipe rebuild is simpler when retained caches are unnecessary.
